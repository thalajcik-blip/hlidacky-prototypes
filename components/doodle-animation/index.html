Doodle Icon Animation — Engineering Handoff

1 · What the designer hands over

One JSON file for the entire icon set. Not one per icon, not one per colour. The preset is global: it applies identically to every variant and every colour, because the animation is derived from each file's own geometry rather than authored per icon.

The Lookbook parameters (variant, color, size, format, loading) are unrelated to this. They select which asset renders; the preset describes how any asset animates. Nothing about them changes.

The JSON is produced by the Export JSON button in this tool.

Classification rule, applied at build time:

inherit `stroke` down through ancestor <g> elements
  stroke set and != "none"  ->  STROKE bucket
  otherwise, fill != "none" ->  FILL bucket
Why this matters: classification is fully structural, so the build step re-derives it on every run. No layer has to be named or tagged by hand — which is the only reason this is tractable across 975 files, and why a re-export from Figma cannot break it.

3 · The model — three buckets plus a composition layer

Stroke length distribution is bimodal, not a smooth curve. Half of all strokes are tick marks, sparkles and dots; only a quarter are real contours. A naive "draw every stroke" animation therefore looks broken on roughly a third of the set, because most of what it draws is 4 units long inside a 72-unit box.

BucketSelectorAnimation
Contoursstroke, length ≥ threshold stroke-dashoffset draw-on
Accentsstroke, length < threshold scale/opacity pop — never drawn
Fillsno strokefade, optional scale or rise
Compositionthe whole icon rotate + zoom on a wrapper, independent timeline

Threshold — the one number that matters

An icon fails if fewer than 3 drawable contours remain. Measured over all 195:

Ship a threshold between 6 and 10. Above 10, icons such as phone, shield-guarantee, sitter-female and whatsapp lose every drawable contour and merely pop into place. At 8 the weakest icon still has 4 contours. All bundled presets sit inside this band.

Draw speed

Bake the measured length into each path at build time and drive stroke-dasharray / stroke-dashoffset from it, so a long contour and a short one draw at the same visual speed. Normalising with pathLength="1" is simpler but makes every stroke take equal time regardless of length, which reads as inconsistent velocity.

4 · Pipeline

Figma export ──▶ [1] build step ──▶ annotated SVG (195 × 5)
                                         │
  preset JSON ──▶ [2] CSS tokens ────────┤
                                         ▼
                                 [3] runtime in the component

[1] Build step (asset pipeline)

Runs over the exported SVGs on every build. For each geometry element: classify, measure, and annotate. Emit the bucket as a class, the length and the stagger index as custom properties:

<path class="dl-c" style="--l:118.4; --i:0" .../>   <!-- contour -->
<path class="dl-a" style="--i:3" .../>             <!-- accent  -->
<path class="dl-f" style="--i:1" .../>             <!-- fill    -->

[2] Preset JSON → CSS custom properties

A small generated stylesheet, or design tokens:

.doodle-icon-component {
  --dl-contour-dur: 620ms;  --dl-contour-stagger: 55ms;
  --dl-accent-delay: 380ms; --dl-comp-rot: -4deg;  /* … */
}
This is the seam that keeps design in control: changing the animation means editing the JSON and regenerating. No Ruby, no JavaScript.

[3] Runtime

CSS keyframes read those properties. Stagger is calc(var(--i) * var(--dl-contour-stagger)); the draw tween runs from var(--l) to 0. A small Stimulus controller with an IntersectionObserver adds a class when the icon enters the viewport, so it plays once on appear and never replays.

The composition tween must sit on the wrapper element, not on the paths — the paths use transform-box: fill-box so they pop around their own centres, while the composition needs the optical centre of the whole icon. Two different elements, so the two tweens can never fight over transform.

5 · Proposed component API

render UI::Core::DoodleIcon.new(
  variant: :rocket, color: :pink, size: 96,
  animation: :sketch,   # :none | :sketch | :pop | :calm | :snap
)

Named presets are recommended over a boolean even though the preset library is global: an empty state and a success screen usually want different timing, and the cost is one extra entry in the config. animation: false must remain the default so nothing changes at existing call sites.

6 · Preset JSON schema

{
  "threshold": 8,
  "comp":     { "delay": 0,   "dur": 760, "rot": -4, "zoom": 90, "easing": "out" },
  "fills":    { "delay": 0,   "dur": 420, "stagger": 24, "mode": "scale" },
  "contours": { "delay": 0,   "dur": 620, "stagger": 55, "order": "doc", "pace": "const" },
  "accents":  { "delay": 380, "dur": 260, "stagger": 34, "mode": "pop", "order": "rand" }
}
FieldValuesMeaning
thresholdnumber, user units draw/pop split point. Keep within 6–10.
delay, dur, staggerms stagger is the gap between consecutive elements in a bucket
comp.rotdegreesstarting angle, settles to 0
comp.zoompercent starting scale, settles to 100. Above 100 shrinks into place.
comp.easingout · over · soft over overshoots
fills.modefade · scale · rise
contours.order doc · long · short · top · center · rand doc is Figma layer order and is a sensible default
contours.paceconst · fixed const = constant speed (duration scales with length)
accents.mode pop · fade · spin · none

Composition is neutral — and must produce no animation at all, not a no-op tween — when rot is 0 and zoom is 100.

8 · Delivery model — the open decision

Icons currently render as <img src="….svg"> from the CDN. An <img>-embedded SVG is a closed document: page CSS and JS cannot reach inside it, so no hover, scroll or state triggers, and no per-path animation. This splits the work cleanly in two:

LayerNeedsCost
Composition (rotate + zoom) Nothing. Runs on the existing .doodle-icon-component wrapper around the <img>. None. Ships across all 975 assets with no pipeline change.
Contours / accents / fills SVG markup reachable from CSS, i.e. a new inline rendering path (format: :inline). Build step, annotated assets, larger DOM, different caching profile.
Recommended split: ship the composition layer as v1 — it is deployable immediately and independently — and the stroke layers as v2 once the inline-rendering and pipeline questions are settled.

v1 presets — ready to implement today

Set render as to <img> wrapper in the toolbar to preview these. They animate opacity, transform: rotate() and transform: scale() on .doodle-icon-component and touch nothing inside the SVG, so they work on the current markup unchanged:

PresetOpacity fromRotateZoom fromDurationEasing
Fade0%0°100%420 mssoft

All three properties are compositor-friendly, so this costs no layout or paint work. The only integration needed is the wrapper class plus an IntersectionObserver to add it once on entry — no build step, no annotated assets, no inline rendering.

One caveat carried over from the composition layer: scaling the wrapper scales stroke widths with it. At zoom from 72% the strokes start noticeably thinner and thicken as the icon settles. It reads as pen pressure at gentle values; Pop in and Stamp sit at the edge of that.

One shortcut worth weighing for v2: CSS animations declared inside the SVG file do run in an <img>. They cannot be triggered from the page, but since the icons already use loading="lazy" the browser fetches them as they approach the viewport, which approximates play-on-appear for free. It is imprecise — the lazy threshold is generous and a cached second instance plays immediately — but it avoids the inline refactor entirely.

9 · Reduced motion

prefers-reduced-motion: reduce disables all four layers; icons render in their final state with no tween. The composition layer is the most vestibularly risky of the four, so if a partial reduced-motion variant is ever wanted, rotation is the first thing to drop — not the fades.

10 · Acceptance criteria

  1. Threshold in the shipped preset is between 6 and 10 user units.
  2. Zero icons across all 195 variants end up with fewer than 3 drawable contours.
  3. Every geometry element is classified — no silent drops (checklist-extra-item is the canary).
  4. Path lengths are baked at build time, not measured in the browser. Measuring 5508 paths on page load is not acceptable.
  5. Each icon plays once when it enters the viewport and never replays.
  6. No icon's animation exceeds 2.5 s. Current worst case: criminal-record at 29 contours ≈ 2.16 s under the Sketch preset.
  7. Reduced motion renders the final state with no animation.
  8. Re-exporting from Figma and rebuilding reproduces the same result with no manual steps.

11 · Status of this tool

This page is a design-side tuner, not production code. It classifies and measures in the browser at load time, which is fine for 195 icons in a local tool and is exactly what the build step must not do. Its purpose is to pick the numbers that go into the JSON.

Known deviation: the colour switcher retints the pink markup through a global palette table rather than loading the real per-colour assets. The table covers all 11 colours used across the set, but four slots in the real assets deviate from the majority mapping, so a handful of icons will show one element in a slightly different colour than Lookbook does. Accepted deliberately; it affects this tool only, never production output.
